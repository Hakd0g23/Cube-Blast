## ux-loading-pass notes (for qa-verification)

**Pause/resume (GDD sections 10/11) — this was the gap juice-pass flagged as missing entirely, and is a section 15 checklist blocker. It is now fully implemented and verified working, not just present.**

- Added a single virtual clock, `vnow()`, in `src/main.js`, and replaced every `performance.now()` call used for animation timing (boardFlashes, shake, landingAnims, shardArcs, goldFlash, zoomPulse, centerBursts/confetti, idle shimmer/tray-bob, death sequence, pulse callouts — all of it) with `vnow()`. `vnow()` returns `performance.now()` minus accumulated paused time, and pins to the instant pause began while `isPaused` is true. This was a deliberate architectural choice over shifting `startedAt`/`expiresAt` on every individual animation data structure by hand on resume (much higher regression-risk surface, one miss = one animation that silently time-jumps) — a single choke point means every existing and future `vnow()`-based effect gets pause-correctness for free, with no per-effect bookkeeping.
- `P` or `Escape` toggles `setPaused()`. Guarded so pause is only a valid input during "Playing" (matches GDD section 10's condition column) — `setPaused(true)` is a no-op while `state.gameOver`, and the same keydown handler returns early on game-over so it never fights the existing Game Over overlay/Escape-adjacent flows.
- Mid-drag pause (P/Escape pressed while holding a piece) drops the held piece back to the tray (`drag = null` inside `setPaused`) rather than leaving it frozen mid-air in an ambiguous held state — a deliberate small UX decision within scope, not a bug fix elsewhere.
- Pointer input on tray pieces is blocked at the `pointerdown` handler while `isPaused` (`if (isPaused) return;`), and since `drag` is cleared on pause, any in-progress `pointermove`/`pointerup` also becomes a no-op — verified nothing places while paused.
- `index.html`: added `#pauseOverlay` (dims the board via the same `--overlay-bg` custom property Game Over's `#overlay` already uses, centered "Paused — press P to resume" text), a persistent `#controlHint` div under the tray ("Drag a block onto the grid • Fill a row/column to clear • P or Esc to pause", GDD 11 "Playing" state requirement), and a one-line control-hint paragraph added to the existing `#legend` "How to play" panel ("Drag blocks from the tray onto the grid. Fill a full row or column to clear it. Press P or Esc to pause.", GDD 11 "Menu/How to play" state requirement). Both satisfy GDD section 13's "controls shown in How-to-play panel AND as persistent hint under tray" requirement, which was previously unmet (no P/Escape mention existed anywhere in either location, and no persistent under-tray hint existed at all).
- Added `window.__fractureDebug.setPaused(v)` / `.isPaused()` test hooks for deterministic automated pause toggling (matches the existing `placePiece`/`geometry` hook pattern juice-pass already established).

**Loading state (GDD sections 2/13) — verified, not just present:**
